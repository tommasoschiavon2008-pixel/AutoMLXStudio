# Root cause: AutoMLXStudio cannot use the local network

The Mac can reach LM Studio at `http://192.168.1.7:1234/v1/models`: Terminal `curl` receives HTTP 200 and the `qwen/qwen3-4b-2507` model record. The unmodified AutoMLXStudio app fails before any HTTP response. Its Network.framework path is `unsatisfied (Local network prohibited)` on `en7`. CFNetwork records `0/0 bytes`, `NSURLErrorDomain` code `-1009`, and underlying `kCFErrorDomainCFNetwork` code `-1009` with POSIX network error 50. See `PreFix-Network-Denial.log`.

The original built app omitted `NSLocalNetworkUsageDescription` from its effective Info.plist. It was ad hoc signed with no stable Apple team identity. The project had `ENABLE_APP_SANDBOX=NO`; no outgoing sandbox entitlement was relevant. The observed failure precedes ATS, HTTP status checks, JSON decoding, model discovery, and Chat dispatch. The current stored profile uses `192.168.1.7`, port `1234`, HTTP, `/v1`, no authentication, and is enabled. A separate obsolete `.20` profile still exists but does not explain process-wide local-network prohibition.

The networking code mapped URLSession's `.notConnectedToInternet` (`-1009`) to `.connectionLost`, which produced the misleading message “The connection to the remote server was lost” and the health label “Server offline”. That mapping masked the Mac-side restriction.

The repair adds the local-network usage description to both the XcodeGen source configuration and the checked-in Xcode project; the validation build is signed with the Mac's Apple Development identity. A dedicated `.networkUnavailable` mapping now directs the user to the macOS Local Network privacy setting and avoids calling the remote server offline when URLSession reports no usable path for this process. The user still controls the system permission; the app cannot silently grant it.

Apple's [local network privacy technote](https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy) explains the independent Mac app privilege, Terminal's special allowance, the usage-description key, and why an Apple-issued signing identity is needed for reliable macOS identity tracking. Apple's [Info.plist documentation](https://developer.apple.com/documentation/bundleresources/information-property-list/nslocalnetworkusagedescription) explicitly covers direct connections to local hosts.
