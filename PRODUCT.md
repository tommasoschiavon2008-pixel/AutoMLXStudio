# Product

## Register

product

## Users

AutoMLX Studio serves developers and advanced Mac users who run, evaluate, and optimize local MLX language models on Apple Silicon. They work primarily inside a focused desktop tool and need to move quickly between runtime control, model chat, orchestration inspection, quantization, benchmarking, and configuration without leaving the local environment.

## Product Purpose

AutoMLX Studio provides a trustworthy macOS control surface for local MLX inference. Project 5 extends that purpose with observable multi-agent orchestration, image understanding, Voice input/output, and durable project-specific memory while keeping execution and persistence local. Success means users can submit a request, receive a useful answer from the appropriate specialist, understand which operational stages and physical models ran, and retain the existing server, optimization, benchmark, and settings workflows.

## Brand Personality

Precise, restrained, technical. The interface should feel calm and native to macOS, with enough operational detail to inspire confidence and no decorative elements that compete with the work.

## Anti-references

Avoid web-dashboard styling transplanted into a desktop app, ornamental AI imagery, oversized marketing metrics, excessive cards, glass effects, noisy gradients, non-native controls, hidden system state, or orchestration displays that imply work which did not actually execute.

## Design Principles

1. Preserve working paths before adding new capability.
2. Make real system state visible without exposing private model reasoning.
3. Use familiar macOS interaction patterns so the tool recedes behind the task.
4. Keep primary workflows concise, with detail available progressively.
5. Treat performance, local execution, and graceful recovery as product behavior, not implementation details.
6. Distinguish actual model output from deterministic fallback behavior and unavailable optional runtimes.
7. Keep project memory isolated by project and cite only known local source metadata.

## Accessibility & Inclusion

Use native SwiftUI controls and semantic labels wherever possible, preserve keyboard and assistive-technology behavior, maintain readable contrast in macOS dark and light appearances, avoid color-only status communication, and keep motion brief and state-driven while respecting system accessibility preferences.
